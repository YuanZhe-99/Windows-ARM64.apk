# 界面

MyGo 前端（`cmd/windows-arm64-apk`、`internal/gui`），按 `design/` 中的界面构建。它保存应用库和
自己的设置；运行应用是运行时的事，只通过 `internal/winapk` 包访问。在运行时出现之前，它对接
`winapk.Mock`：显示示例应用，并明确说明这是示例。

## 窗口

| 窗口 | 内容 |
|---|---|
| 主窗口 | 窗口底色上的侧边栏，旁边是当前组的窗格，距窗口边缘 8 点；没有标题栏条：右上窗格的标题栏绘制最小化、最大化和关闭，标题栏的空白处可以移动窗口 |
| 应用的独立窗口 | 一个应用，没有侧边栏，从不拆分；标题栏有返回、旋转、回到主窗口、⋯ 和窗口按钮；关闭它就停止应用 |

- **侧边栏。** 隐藏侧边栏和添加 APK…；主页及应用数量；已打开，每组一个条目（单独的窗格是一行，
  多个窗格是一张以它们名称为标题的卡片）；在独立窗口中；设置；运行时状态（可以运行应用 / 暂时
  无法运行应用），点击打开诊断。
- **标签。** 窗格显示主页、诊断或一个已打开的应用。主页从不关闭；它可以与应用拆分，并移入它们
  的组。
- **组。** 组是一棵拆分树（`layout.go`）。向右拆分 / 向下拆分提供其他组的窗格、主页和打开应用…；
  只有两半都能保持 360 × 280 点、且组内少于四个窗格时才提供拆分，否则按钮变灰并说明旁边没有空间 /
  下方没有空间。最大化让一个窗格显示在组的上方，其他窗格继续运行。窄于 560 点的窗格把独立窗口和
  拆分按钮收进 ⋯。空的组会消失，主窗口回到主页所在的组。
- **应用的窗格。** 缩放到窗格中的手机式外框（手机 360 × 720、小平板 600 × 960，或不带外框的
  适应窗格），以及一个工具栏：返回（焦点窗格也可用 Esc）、旋转和屏幕尺寸。画面显示应用的状态：
  正在启动、运行中、没有响应（停止 5 秒无回应后出现，可强制停止）、已停止（再次打开）或未能启动
  （用平常话说明，提供重试、显示详情，受限运行的应用还提供关闭原生代码再试一次）。
- **拖动窗格。** 窗格的标题栏（图标和名称）和侧边栏的行都可以拖动。拖到另一个窗格上时，会显示可放置的
  区域：在有空间的每一侧放在它旁边（左侧、右侧、上方、下方），或放在它的位置（放在这里；被替换的窗格
  单独成组）；在同一个组内只能交换位置（交换位置）。放到侧边栏的列表上会离开所在的组，单独成组。应用的
  窗格在主窗口外松开时，会在独立窗口中打开；在窗口内没有区域的地方松开或按 Escape，则留在原处。从侧边栏
  把独立窗口中的应用拖到窗格上，它会回到主窗口成为那个窗格。
- **打开。** 每个应用默认作为窗格或在独立窗口中打开（在它的详情中设定；新应用跟随“设置 › 常规”）。
  “打开”使用默认方式；▾ 临时提供作为窗格打开、在当前窗格旁打开和在独立窗口中打开。已经打开的应用
  会在原处显示到前面。在窗格和窗口之间移动时，请运行时重新挂接画面（`Process.Reattach`），做不到时
  重新启动应用。
- **它的屏幕。** 应用打开时以及屏幕变化时（旋转、新的屏幕尺寸、适应窗格和它的窗口的空间变化），都会
  被告知屏幕尺寸。独立窗口按应用的屏幕尺寸打开，旋转时随之转向。
- **添加 APK。** 添加 APK…（Ctrl+O）、把 `.apk` 拖到主窗口的任何位置，或在命令行或第二次启动时给出一个
  APK，都会打开“添加应用”；不会把 Windows-ARM64.apk 注册为 `.apk` 文件的打开方式。APK 不在原处的应用
  显示找不到文件和查找…，读取选中的文件并保留应用的设置。
- **按键。** Ctrl+O 添加 APK，Ctrl+W 关闭焦点窗格（主页保留），Ctrl+, 打开设置，Esc 是焦点应用的返回。
  主窗口的标题是焦点窗格的名称。
- **关闭主窗口**会停止窗格中的应用。开启“先询问”时，对话框列出哪些会停止、哪些继续运行，并有
  “不再询问”。独立窗口中的应用继续运行，除非“常规”设为停止所有应用。

## 面板和对话框

| 面板 | 内容 |
|---|---|
| 添加应用 | `Inspect` 的结果：名称、版本、包名、大小、用平常话说的结论、包含的内容、打开方式；添加到应用库或添加并打开。说明文件中的任何内容都没有运行 |
| 应用详情 | 在这里能用的、上次的失败、打开方式、屏幕尺寸、移除应用…；高级：原生代码关闭或受限及 profile（使用默认、N0、N1、N2）、图形 |
| 设置 | 常规（新应用的打开方式、关闭主窗口、先询问、应用数据的打开文件夹和移动…、语言、外观）；运行时（使用哪个 Java 运行时、更新 / 重新安装、保持最新、默认图形、默认原生执行 profile）；关于 |
| 获取 Java 运行时 | 未找到时窗格上方的卡片，以及逐步的对话框（下载、检查、安装、测试），可隐藏和取消 |
| 确认 | 有窗格应用时关闭主窗口；移除应用 |

诊断是一个窗格：这台电脑（`doctor` 报告，示例数据上有示例横幅）和应用日志：每个应用自 Windows-ARM64.apk 启动以来最近的十次运行（何时开始、如何结束），所选运行的日志
及其错误类别，只显示错误和警告、复制日志和保存以提交错误报告…。窗格关闭后，运行的日志仍然保留。
只有诊断显示错误类别、路径和版本；窗格和主页用平常话说明发生了什么。

## 文件

| 文件 | 内容 |
|---|---|
| `%APPDATA%\Windows-ARM64.apk\demo\gui.json` | 界面的设置（`Prefs`）：主题、语言、新应用的打开方式、关闭、应用数据文件夹、Java 文件夹、保持最新、默认图形和 profile、侧边栏是否隐藏 |
| `library.json`（同一文件夹） | 应用库（`entry`）：每个 APK 的 `Inspect` 结果和用户为它做的选择；显示示例应用库时不写入 |

两者都以原子方式写入（临时文件改名覆盖旧文件）；文件缺失或损坏时使用默认值。`demo` 文件夹把示例
运行与真实运行分开。

## 运行时 ↔ 前端契约（草案）

`internal/winapk` 是界面对运行时的期望，在运行时出现之前从界面一侧写成；运行时 Agent 把它变成
`winapk` CLI 和每个 APK 一个的运行时进程，需要不同之处，在同一变更中同时修改这个包和视图。

| 调用 | 期望运行时提供 |
|---|---|
| `Doctor(ctx, javaHome)` | `winapk doctor --json`：`Report`，包括找到的 Java 运行时（自带或选定、是否原生 ARM64）、机器信息，以及每项功能的级别（`works`、`experimental`、`unavailable`） |
| `Inspect(ctx, path)` | `winapk inspect --json`：`APK`，包括包名、标签、版本、大小、SDK 级别、ABI、原生库、GLES/Vulkan 使用、所需的最低 profile、结论（`can-run`、`needs-native`、`not-yet`、`unsupported`）和启动器图标；不运行任何东西 |
| `Launch(spec, report)` | 每个 APK 一个运行时进程；`State` 更新（`starting`、`running`、`not-responding`、`stopped`、带 `PLAN.md` §14.2 类别的 `failed`、图形后端、日志），直到进程结束 |
| `Process.Stop`、`Kill`、`Back`、`Resize` | 请求关闭、立即结束、Android 返回、以 DIP 计的屏幕尺寸 |
| `Process.Reattach(window)` | 不重启地把画面在窗格和独立窗口之间移动，或报告做不到 |
| `InstallJava(ctx, dir, progress)` | 在 `dir` 中获取、校验、安装并测试私有 Java 运行时，报告进行到哪一步 |

草案中还没有、因此界面也还没做的：把应用的画面交给窗格或窗口（计划不规定具体技术）、移动应用数据
文件夹的内容、应用数据和转换后代码的大小、清除转换后的代码，以及私有 Java 运行时的自动更新（界面
保存这个设置；更新由运行时完成）。

## 示例数据

`winapk.Mock` 代替运行时：设计中的六个示例应用、标记为 `Demo` 的示例 `doctor` 报告、只报告状态的
进程（受限运行的 Tile Puzzle 以 `GUEST_SYMBOL_UNRESOLVED` 失败；Vulkan Cube 和 Old Calc 以暂不支持 /
不支持失败），以及只走一遍进度的 Java 安装。不从 APK 读取任何内容，也不运行任何东西；画面和诊断会
说明这一点。`WINAPK_FRESH=1` 以空的应用库、没有 Java 运行时启动。
